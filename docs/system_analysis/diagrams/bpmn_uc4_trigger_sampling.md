# BPMN v1 — UC4: Формирование задания на внеплановый (триггерный) отбор пробы

**Версия:** 0.1 (C-04, I-6). **Независимо от вилки A/B.**
Система не управляет роботом-сэмплером — инициирует рабочий процесс для живого лаборанта (In-Scope, `04_use_cases.md`). FR-07, FR-08.

## Дорожки

1. **Система AquaPredict**
2. **«БИТ.Лаборатория» (1С)**
3. **Лаборант**

## Поток

| № | Дорожка | Шаг / элемент | Тип |
| --- | --- | --- | --- |
| 1 | Система | Вход: высокий риск отклонения (из UC2; например, рост мутности TEL-06) | старт |
| 2 | Система | Генерация задания «Внеплановый отбор пробы» для конкретной партии, приоритет «Срочно»; запись в 1С через HTTP-сервис (FR-07) | задача |
| 3 | 1С | Задание в модуле отбора; уведомление лаборанту штатными средствами 1С (канал — открытый вопрос 2) | задача |
| 4 | Лаборант | Физический отбор пробы у линии: стерильная тара, маркировка (вне систем) | задача (HITL) |
| 5 | Лаборант | Сканирование штрихкода пробы в 1С — подтверждение факта отбора; далее — стандартный лабораторный анализ (Chain of Custody ведёт 1С) | задача |
| 6 | Система | Чтение статуса задания и пробы по OData; сохранение ссылки «инцидент → задание → проба» | задача (FR-07, FR-08) |
| 7 | Система | Автоматическая связка «проба → срез телеметрии за окно (2 ч)» — Feature Vector + лабораторный результат как метка | задача (FR-08, UC6) |
| 8 | 1С | Лабораторный анализ, протокол испытаний (ground truth) | задача |
| 9 | Система | Результат в связке «инцидент → проба»: True Positive / False Positive → пополнение обучающей выборки (FR-11, UC6) | конец |

## Границы

- Приоритет метки: лабораторный протокол > вердикт технолога (FR-11, «золотой стандарт» данных, UC6).
- Двойной ввод исключён: журнал проб и ввод результатов — только в 1С (FR-08, вариант A).

## Для бэклога (I-6)

Кандидаты в истории: автогенерация задания в 1С; уведомление лаборанта; трекинг статуса задания/пробы; связка «инцидент → задание → проба → телеметрия».

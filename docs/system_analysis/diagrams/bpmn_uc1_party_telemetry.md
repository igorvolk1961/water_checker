# BPMN v1 — UC1: Синхронизация производственной партии и привязка к потоку данных датчиков
> **Канонический BPMN:** `bpmn/uc1.bpmn` (BPMN 2.0, bpmn.io / Camunda Modeler) · схема: `bpmn/uc1.svg`


**Версия:** 0.2 (C-04, I-6; переименование UC1 и правки варианта A — по редакции ведущего от 2026-10-12). FR-01, FR-02, FR-15.
В варианте A партия создаётся **в «БИТ:LIMS»** — собственный журнал партий в AquaPredict отсутствует; система синхронизирует партию и связывает телеметрию с её идентификатором.

## Дорожки

1. **«БИТ:LIMS» (1С)**
2. **Система AquaPredict**
3. **Линия розлива / IoT-шлюз**

## Поток

| № | Дорожка | Шаг / элемент | Тип |
| --- | --- | --- | --- |
| 1 | 1С | Регистрация производственной партии (штатный процесс 1С, номер партии — источник прослеживаемости) | старт |
| 2 | Система | Чтение новой партии по OData (в составе пакета, ≤ 60 запросов/мин — NFR-6) | задача (FR-15) |
| 3 | Система | Регистрация начала наблюдения за партией; привязка временных рядов телеметрии к идентификатору партии | задача (FR-01) |
| 4 | Линия/шлюз | Поток телеметрии TEL-01…TEL-13 по OPC-UA / MQTT, частота ≥ 1 раз/мин; буферизация до 2 ч при потере связи с автосинхронизацией | задача (FR-02, NFR-2/3) |
| 5 | Система | Контроль качества потока: пропуски, «замороженные» значения, выход за физический диапазон → события для инженера КИПиА (SCR-09); пометка достоверности канала | задача (FR-16) |
| 6 | Система | Партия наблюдается: скоринг запущен (UC2) | конец основного |
| 7 | 1С | Попытка закрытия партии | событие |
| 8 | Система | Есть непроверенные предиктивные инциденты по партии? | шлюз (FR-01) |
| — | — | **Да** → задача/комментарий в 1С «закрытие блокировано до проверки инцидентов» → проверка инцидентов (UC3) → возврат к шлюзу | — |
| — | — | **Нет** → партия закрывается штатно в 1С | конец |

## Границы

- AquaPredict не создаёт и не редактирует партии — только читает (вариант A, FR-15).
- Запись в 1С от системы — только статусы/комментарии о блокировке закрытия (FR-01) и задачи (UC2–UC4).

## Для бэклога (I-6)

Кандидаты в истории: чтение партий по OData; привязка телеметрии к партии; приём/буферизация потока; контроль качества потока (FR-16); блокировка закрытия партии.

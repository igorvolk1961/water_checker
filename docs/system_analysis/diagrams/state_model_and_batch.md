# State v1 — Партия, Baseline-профиль, ML-модель, синхронизация с 1С

**Версия:** 0.1 (C-05). Формализация состояний ST-05…ST-07 и состояния партии (FR-01). Термины — `02_glossary.md`.

## 1. Партия (FR-01)

```mermaid
stateDiagram-v2
    state "Наблюдается" as P1
    state "Закрытие блокировано" as P2
    state "Закрыта" as P3
    [*] --> P1 : партия прочитана из 1С (OData), начало наблюдения (FR-01.1)
    P1 --> P2 : попытка закрытия в 1С при непроверенных инцидентах (FR-01.4)
    P2 --> P1 : все инциденты [Закрыт / Отклонён]
    P1 --> P3 : штатное закрытие в 1С
    P3 --> [*]
```

Инварианты: партия создаётся/закрывается только в 1С (вариант A); система лишь записывает статус/комментарий блокировки (FR-15.2).

## 2. Baseline-профиль (ST-06, FR-10)

```mermaid
stateDiagram-v2
    state "Черновик" as B1
    state "Эталонный" as B2
    state "Архив (заменён)" as B3
    [*] --> B1 : обучение на архиве (Anomaly Detection, FR-10.3)
    B1 --> B2 : подтверждение ГТ (фиксация в аудите, UI-07)
    B2 --> B3 : заменён новой версией (после критериев перехода)
    B3 --> [*]
```

Инварианты: до [Эталонный] Shadow-метрики накапливаются, но персоналу не показываются (FR-04.2).

## 3. ML-модель (ST-05, FR-04, FR-11)

```mermaid
stateDiagram-v2
    state "Shadow" as M1
    state "Advisor" as M2
    state "Production" as M3
    state "Архив" as M4
    state "Откат (drift)" as M5
    [*] --> M1 : обучение/Pre-training, критерии перехода не выполнены
    M1 --> M2 : критерии §4 выполнены (Recall ≥ 0,75 при FPR ≤ 0,10, ≥ 4 нед стабильности, ≥ N инцидентов)
    M2 --> M3 : утверждение DS («Утвердить и развернуть», HITL)
    M3 --> M5 : деградация метрик (Data Drift) или конфликт переобучения (поток 6а)
    M5 --> M1 : возврат в накопление метрик
    M1 --> M4 : версия заменена
    M2 --> M4 : версия заменена
    M3 --> M4 : версия заменена
    M4 --> [*]
```

Инварианты: перевод Shadow → Advisor — по утверждённым критериям, решение фиксируется; в Shadow прогнозы персоналу не показываются; журнал версий ведётся (FR-11.4); мониторинг дрейфа непрерывен (LGL-13, FR-11.6).

## 4. Синхронизация с 1С (ST-07, FR-15)

```mermaid
stateDiagram-v2
    state "Норма" as S1
    state "Очередь" as S2
    state "Ошибка" as S3
    [*] --> S1
    S1 --> S2 : нагрузка → пакетирование, лимит ≤ 60 запросов/мин (NFR-6)
    S2 --> S1 : очередь разгружена
    S1 --> S3 : 1С недоступна / отказ
    S2 --> S3 : 1С недоступна / отказ
    S3 --> S2 : восстановление → ретраи, досинхронизация
    S3 --> S1 : полная досинхронизация
```

Инварианты: приём телеметрии и скоринг при [Ошибка] продолжаются (FR-15.5); записи задач/статусов буферизуются; UI показывает время последней успешной синхронизации (UI-08).

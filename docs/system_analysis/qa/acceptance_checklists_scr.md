# Поэкранные чек-листы приёмки (SCR-01…SCR-12)

**Версия:** 0.1 (2026-10-13). **Автор:** коллега (зона UI). **Назначение:** приёмка экранов заказчиком/ведущим по этапам R0–R2; каждый пункт опирается на `ui_requirements.md` v0.3 и FR. Отмечается ✅ при приёмке; расхождения — в дефект-лист этапа.

## R0 — каркас

### SCR-01 Дашборд технолога
- [ ] Лента алертов сортируется по риску и времени; критический — красное выделение + звук (NFR-4)
- [ ] Кнопка «Подтвердить ознакомление» у критического алерта; подтверждение без него повторяется (UI-01, UI-SCR-01.3)
- [ ] Бюджет алертов за час / лимит 10 виден (NFR-5)
- [ ] Источник скоринга помечен (Слой 1/Слой 2) (UI-SCR-01.4)
- [ ] Индикатор синхронизации с 1С в шапке, баннер при ошибке (UI-08)
- [ ] Дисклеймеры вероятности и HITL на экране (UI-03/04)

## R1 — ядро демо

### SCR-02 Карточка инцидента
- [ ] Вердикт — отдельная сущность `ВердиктИнцидента` [Подтверждён / Ложное срабатывание] + причина из справочника (В-1)
- [ ] Результат КА [Выполнено / Отменено] показывается отдельно от вердикта (US-05.1)
- [ ] Тренд TEL-параметров за окно 2 ч; порог рабочей точки подписан с датой утверждения (LGL-09)
- [ ] Дисклеймер «ML-алерт не основание для браковки» (LGL-11)
- [ ] Действия пишутся в аудит с источником (LGL-10)

### SCR-03 Задачи поверх 1С
- [ ] Список задач read-only, статусы и история из 1С (UI-06, ST-03)
- [ ] Приоритет «Срочно» выделен; фильтры по партии/статусу/исполнителю
- [ ] При ошибке синхронизации список замораживается с временем последней успешной синхронизации (UI-SCR-03.5)
- [ ] Нет кнопок изменения задачи в веб-консоли — переход в 1С

### SCR-12 Уведомления
- [ ] Push/SMS содержат партию, параметр, риск-скор, горизонт + глубокую ссылку
- [ ] Подавленные как дубль помечены (NFR-5); канал лаборанта — только 1С (OQ-04)

## R2 — советник

### SCR-04 Аналитика по партии
- [ ] Телеметрия + результаты LAB на одной оси; связка «проба → срез 2 ч» (FR-08.4)
- [ ] Сверка с нормативом — подсветка информационная, решение — в 1С (LGL-11)
- [ ] Экспорт CSV для DS фиксируется в аудите (UI-07)

### SCR-05 Статусы протоколов и ФГИС
- [ ] Статусы: Валидирован → Подписан (ПЭП РЛ, 1С) → Выгружен → UUID (FR-09.3)
- [ ] Неподписанный протокол не отображается как «отправляемый» (LGL-07); кнопок выгрузки/подписи нет

### SCR-06 Метрики модели
- [ ] Цели и значения по Слоям (не «Фазам») + колонка Baseline (`kpi.md` §2)
- [ ] Рабочая точка: порог, остаточные FPR/FNR, «утверждено эксплуатантом» (LGL-09)
- [ ] Изменение порога отсюда невозможно — ссылка на SCR-11

### SCR-07 MLOps-модуль
- [ ] Очередь разметки, карантин конфликтов (не используется в обучении — FR-11.2)
- [ ] Сравнение метрик версий; «Утвердить и развернуть» — только DS (HITL)
- [ ] Откат при дрейфе с флагом «Требуется проверка аномалий» (UC6 6а)

### SCR-08 Cold Start
- [ ] Мастер: импорт → отчёт о матчинге (доля, причины) → Baseline → подтверждение ГТ «Эталонный» (FR-10)
- [ ] Поток 7а: предложение Pre-training на синтетике с продлением калибровки

## R2/R3 — сквозные

### SCR-09 Мониторинг канала телеметрии
- [ ] Статусы датчиков: Норма / Нет данных / Заморожено / Вне диапазона / Задержка (FR-16.1)
- [ ] Буфер шлюза: заполнение, глубина ≤ 2 ч, прогресс синхронизации (FR-16.2)
- [ ] Инциденты по деградировавшему каналу помечены пониженной достоверностью (FR-16.4)

### SCR-10 Аудит-лог
- [ ] Различение «рекомендация системы / решение человека / фактическое действие» + источник (LGL-10)
- [ ] Записи неизменяемы; фильтры по периоду/роли/сущности/источнику; выгрузка CSV — РЛ/АДМ и фиксируется

### SCR-11 Администрирование
- [ ] RBAC-роли; изменение рабочей точки — только АДМ, с историей «было/стало» (LGL-09)
- [ ] Справочник нормативов с версией/датой; лимит ≤ 60 запросов/мин виден (NFR-6)
- [ ] Параметры ПДн: маскирование, сроки (LGL-05/06)

### SCR-05/03 зависимость
- [ ] Баннер деградации 1С блокирует ввод там, где данные недоступны (UI-08, ST-07)

## Порядок применения

1. Перед актом этапа: прогнать чек-листы экранов этапа + NFR-замеры (`test_plan_draft.md` §4).
2. Каждый непройденный пункт → дефект с критичностью; критические блокируют акт.
3. Пройденные чек-листы прикладываются к акту этапа (ТЗ §7.2).

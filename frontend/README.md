# Frontend — веб-консоль AquaPredict (Jinja2 + HTMX)

**Решение OQ-12 (ведущий, 2026-10-13):** server-rendered **Jinja2 + HTMX + Chart.js**, без node-сборки. Презентация на заказчика и макеты — не теряют актуальности: макеты `mockups/` остаются визуальным эталоном, шаблоны здесь повторяют их разметку.

## Структура

```
frontend/
├── README.md                ← этот файл
├── static/
│   ├── css/
│   │   ├── tokens.css       ← дизайн-токены (из design_system.html, единственный источник)
│   │   └── app.css          ← базовые компоненты (шапка, баннер UI-08, таблицы, бейджи, дисклеймеры)
│   └── js/                  ← (позже) точечные скрипты HTMX-хелперов
├── templates/
│   ├── base.html            ← каркас страницы: шапка, RBAC-меню, индикатор синхронизации (UI-08)

│   ├── incident.html        ← SCR-02 (карточка инцидента, вердикт ВердиктИнцидента)
│   ├── tasks.html           ← SCR-03 (задачи поверх 1С, read-only, фильтры через HTMX)

│   ├── party.html           ← SCR-04 (аналитика партии, Chart.js, сверка LAB информационно)
```

## Как подключается к бэкенду (стыковка с ведущим)

- FastAPI монтирует: `app.mount("/static", StaticFiles(directory="frontend/static"))` и рендерит шаблоны из `frontend/templates` через `Jinja2Templates(directory="frontend/templates")`.
- Контекст шаблонов = формы из **API-контракта** (`../docs/system_analysis/reviews/2026-10-13_frontend_api_contract_draft.md`): `/alerts`, `/incidents/{id}`, `/metrics/model` и т. д. Названия полей в шаблонах совпадают с контрактом (`risk_score`, `horizon`, `source`, `status`).
- HTMX: взаимодействие без перезагрузки (подтверждение ознакомления, фильтры, вердикт) — endpoint'ы возвращают фрагменты HTML.
- **Frontend никогда не обращается к 1С напрямую** — только к API (NFR-6 на бэкенде).
- Графики — Chart.js (CDN) на SCR-02/04/06.

## Правила, зашитые в шаблоны (не удалять при доработках)

- **UI-01/NFR-4:** критический алерт — красный, звуковой сигнал, обязательное подтверждение ознакомления.
- **UI-08/ST-07:** баннер синхронизации с 1С в шапке каждой страницы (`X-Sync-Status`).
- **UI-03/04/11:** дисклеймеры вероятности, HITL и «ML-алерт ≠ браковка» — на всех экранах с прогнозом.
- **В-1:** вердикт `ВердиктИнцидента` (значение + причина из справочника) — отдельно от результата корректирующего действия.
- **UI-06/LGL-07:** данные 1С — только чтение; кнопок «выгрузить/подписать» не существует.
- **В-4/терминология:** «корректирующее действие» в прозе, CA- в идентификаторах; Слой 1/Слой 2; Production/Active разведены.

## Демо-данные

Шаблоны самодостаточны для просмотра: fixture-данные передаются контекстом (см. `templates/*.html` — блоки `{# fixture #}`); при подключении реального API fixture заменяется контекстом роутов. Данные помечены как примеры и не являются показателями проекта.

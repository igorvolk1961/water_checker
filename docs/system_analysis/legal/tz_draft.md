# Техническое задание — черновик (Technical Specification / ТЗ)

> **Черновик для учебного проекта.** Составлено по структуре ГОСТ 34.602-89 (адаптировано). Опирается на артефакты проекта (`01…10`, `requirements/`, `diagrams/`, `kpi.md`, `hardware_requirements.md`, `cost/`, `plans/`). Поля `___` — заполнить.

## 1. Общие сведения

1.1. **Наименование системы:** AquaPredict — предиктивная аналитика качества бутилированной воды (аналитическая надстройка над «БИТ.Лаборатория»).
1.2. **Заказчик:** __________. **Исполнитель:** __________.
1.3. **Основание:** договор № ___ от ___ (Приложение № 1).
1.4. **Сроки:** R0–R3 (см. §5). **Порядок финансирования:** фазовое.
1.5. **Позиционирование:** вариант A — надстройка; лабораторный контур (пробы, результаты, протоколы, ФГИС) остаётся в 1С (`01_vision_and_scope.md`).

## 2. Назначение и цели

2.1. **Назначение:** раннее предупреждение о риске выхода показателей качества воды за нормы СанПиН на основе телеметрии линии и ML.
2.2. **Цели:** снижение доли брака; сокращение потерь; соответствие нормативам (ТР ЕАЭС 044/2017, СанПиН 1.2.3685-21); юридически значимый цифровой след.
2.3. **Принцип:** HITL — система рекомендует, решение принимает человек.

## 3. Характеристика объектов

3.1. Производственная линия розлива (водоподготовка, обратный осмос, озонирование, УФ, розлив) — источник телеметрии (TEL-01…13).
3.2. Лаборатория и «БИТ.Лаборатория» (1С) — источник утверждённых результатов (LAB-01…16) и приёмник задач.
3.3. SCADA Historian заказчика (шаг ≤ 1 мин, хранение ≥ 3 лет) — источник архива для обучения.

## 4. Требования к системе

### 4.1. Требования к системе в целом

- Интеграция с 1С (OData чтение / HTTP запись) с лимитом **≤ 60 запросов/мин** (NFR-6).
- Приём телеметрии OPC-UA/MQTT, частота ≥ 1 изм./мин, latency «датчик→алерт» **≤ 5 с** (NFR-1/3), буферизация **до 2 ч** (NFR-2).
- Двухслойный риск-скоринг: **Слой 1 (rule-based)** и **Слой 2 (ML)**; цель по слоям — `kpi.md` §2.
- Бюджет алертов **≤ 10/час** (NFR-5); конфигурируемый порог (рабочая точка).
- Веб-консоль технолога (SCR-01…12), без отдельного интерфейса для лаборанта (работа в 1С).

### 4.3. Требования к видам обеспечения

- **Математическое/ML:** Слой 1 — правило-ориентированный движок; Слой 2 — ML-модель (scikit-learn); Baseline — Anomaly Detection (Unsupervised); Pre-training — цифровой двойник (`10_cold_start_and_archival_data.md`).
- **Информационное:** параметры TEL-01…13 и LAB-01…16 (`requirements/measured_parameters.md`); retention 1 год (LGL-06).
- **Программное:** стек — `architecture_stack.md` (FastAPI/Pydantic, PostgreSQL/SQLAlchemy/Alembic, Redis, httpx/asyncua/paho-mqtt).
- **Техническое:** оборудование и инфраструктура — `hardware_requirements.md`; поставляет Исполнитель.
- **Организационное:** роли и матрица прав (SCR, FR-14); процессы HITL, обучение персонала.
- **Правовое:** юридические требования LGL-01…14 (`legal/legal_risks_and_requirements.md`); подписание протокола — ПЭП руководителя лаборатории в контуре 1С.

### 4.4. Требования к надёжности, безопасности, документированию

- Доступность ≥ 99 %; резервирование и backup; NTP-синхронизация.
- Безопасность: RBAC, TLS, аудит-лог «рекомендация/решение/действие» (LGL-10), защита ПДн (ФЗ-152).
- Валидация ПО по ГОСТ ISO/IEC 17025-2019.
- Документирование — §8.

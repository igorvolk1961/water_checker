# State v1 — Алерт, предиктивный инцидент, задача, вердикт

**Версия:** 0.1 (C-05). **Независимо от вилки A/B** (вопрос вилки закрыт — вариант A).
Формализация состояний ST-01…ST-04 из `requirements/ui_requirements.md` §6. Термины — `02_glossary.md`; источники — FR-05, FR-06, FR-07, FR-12.

## 1. Алерт (ST-01, FR-05)

```mermaid
stateDiagram-v2
    state "Новый" as A1
    state "Ознакомлен" as A2
    state "В работе" as A3
    state "Закрыт" as A4
    state "Подавлен (дубль)" as A5
    [*] --> A1 : RiskAlert сгенерирован (NFR-1 ≤ 5 с)
    A1 --> A2 : подтверждение ознакомления ГТ (критический — обязательное, NFR-4)
    A2 --> A3 : создан предиктивный инцидент
    A3 --> A4 : инцидент Закрыт / Отклонён
    A1 --> A5 : бюджет алертов превышен (NFR-5), дубль приоритизирован
    A5 --> A4 : архивация
    A4 --> [*]
```

Инварианты: каждое подтверждение ознакомления фиксируется в аудите (кто/когда, LGL-10); признак источника [Слой 1 / Слой 2] не меняется.

## 2. Предиктивный инцидент (ST-02, FR-06)

Статусы — по доменной модели ведущего (`06_domain_model.md`, правка от 2026-10-12): [Новый / Подтверждён / Ложный_алерт / Закрыт].

```mermaid
stateDiagram-v2
    state "Новый" as I1
    state "Подтверждён" as I2
    state "Ложный_алерт" as I3
    state "Закрыт" as I4
    [*] --> I1 : создан по алерту
    I1 --> I2 : технолог подтвердил риск (UC2), создана задача КА в 1С
    I1 --> I3 : технолог пометил ложное срабатывание + причина из справочника
    I2 --> I1 : результат КА [Отменено] — возврат на пересмотр (FR-06.6)
    I2 --> I4 : КА выполнено (UC3) и, при необходимости, лабораторный контроль
    I3 --> I4 : false positive учтён для обучения (UC6)
    I4 --> [*]
```

Инварианты: пока инцидент не в [Закрыт] — закрытие партии в 1С блокировано (FR-01.4); переход в терминальный статус требует вердикта (ST-04 обязателен); статус «Ложный_алерт» относится к инциденту, а результат КА [Выполнено / Отменено] — к задаче (устранение дефекта US-05.1); вердикт уходит в разметку как прокси-метка (FR-12).

## 3. Задача КА / задание отбора (ST-03, FR-06.3/06.4, FR-07)

```mermaid
stateDiagram-v2
    state "Создана (в 1С)" as T1
    state "Назначена" as T2
    state "Выполнена" as T3
    state "Отменена" as T4
    [*] --> T1 : запись через HTTP-сервис (рекомендованные шаги, приоритет)
    T1 --> T2 : назначение исполнителя в 1С, уведомление штатными средствами 1С
    T2 --> T3 : закрытие в 1С с приложениями (фото/комментарий) — результат [Выполнено]
    T2 --> T4 : результат [Отменено] → инцидент возвращается ГТ (FR-06.6)
    T3 --> [*]
    T4 --> [*]
```

Инварианты: статусы синхронизируются из 1С (система — читатель, UI-06); время выполнения и исполнитель фиксируются в 1С (LGL-10); ошибка синхронизации → ST-07 [Ошибка], список замораживается (UI-SCR-03.5).

## 4. Вердикт по инциденту (ST-04, FR-06.5, FR-12)

```mermaid
stateDiagram-v2
    state "Подтверждён" as V1
    state "Ложное срабатывание" as V2
    state "Метка в выборке" as V3
    state "Карантин (конфликт)" as V4
    [*] --> V1 : решение ГТ (HITL, LGL-04)
    [*] --> V2 : решение ГТ + причина из справочника
    V1 --> V3 : + лабораторный протокол → True Positive (FR-11.1)
    V2 --> V3 : прокси-метка (приоритет ниже лабораторного протокола)
    V2 --> V4 : расхождение с лабконтролем → не используется в обучении (FR-11.2)
    V4 --> V3 : разрешение конфликта DS (приоритет — протокол)
```

Инварианты: вердикт ≠ результат КА (сущности раздельны, устранение дефекта US-05.1); вердикт обязателен перед терминальным статусом инцидента.

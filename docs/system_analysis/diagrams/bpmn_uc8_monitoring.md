# BPMN v1 — UC8: Мониторинг источников телеметрии (КИПиА)

**Версия:** 0.1 (черновик ведущего к утверждению коллегой; C-04, I-6). **Вариант A.**
Обеспечение достоверности канала телеметрии: контроль датчиков, обнаружение аномалий и пропусков (UC8, `04_use_cases.md`; FR-16, NFR-2). Закрывает функциональную дыру G-3 ревью.

## Дорожки

1. **Система AquaPredict**
2. **Инженер КИПиА**
3. **IoT-шлюз / SCADA**

## Поток

| № | Дорожка | Шаг / элемент | Тип |
| --- | --- | --- | --- |
| 1 | Система | Фоновый контроль: доступность датчиков TEL-01…13, целостность потока (пропуски, «замороженные» значения, выход за физический диапазон) | старт (FR-16.1) |
| 2 | Шлюз | Буферизация при потере связи до 2 ч; автосинхронизация в исходном порядке после восстановления | задача (NFR-2) |
| 3 | Система | Классификация статуса датчика: [Норма / Нет данных / Заморожено / Вне диапазона / Задержка потока] | задача (FR-02.4, FR-16.1) |
| 4 | Система | При деградации — диагностическое уведомление инженеру КИПиА (SCR-12); события качества доступны с историей (SCR-09) | задача (FR-16.2/16.3) |
| 5 | Система | Пометка достоверности: инциденты/алерты по деградировавшему каналу получают признак пониженной достоверности | задача (FR-16.4) |
| 6 | Инженер КИПиА | Устранение неисправности (вне систем) | задача (HITL) |
| 7 | Инженер КИПиА | Подтверждение восстановления канала в консоли | задача |
| 8 | Система | Снятие признака недостоверности; возврат источника в риск-скоринг | конец |

## Границы

- Система не управляет оборудованием (Out-of-Scope `01_vision_and_scope.md`): только диагностика и уведомление.
- Мониторинг канала — условие достоверности прогноза (связь с NFR-2, буферизация).

## Для бэклога (I-6)

Кандидаты в истории: статус датчиков; вьюер буфера шлюза; уведомления КИПиА; пометка достоверности инцидентов; история событий качества.

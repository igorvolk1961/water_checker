# AquaPredict LIMS — Спецификация варианта использования (Detailed Use Case)

Самый важный артефакт для демонстрации глубины проработки. Взят главный отличающий сценарий.

## Обработка предиктивного предупреждения о риске отклонения качества

- **Основной актер:** Главный технолог.
- **Вторичный актер:** ML-Модуль.
- **Предусловие:** производственная линия работает, данные с датчиков поступают в систему, ML-модель активна.

### Основной поток (Main Flow)

1. ML-Модуль непрерывно анализирует агрегированные данные с датчиков (например, падение давления на фильтре + рост температуры в цеху).
2. ML-Модуль вычисляет вероятность отклонения показателя (например, ОМЧ) свыше нормы в ближайшие 2 часа > 80 %.
3. ML-Модуль отправляет в систему событие `RiskAlert` с параметрами: `партия_id`, `параметр_риска`, `вероятность`, `рекомендуемое_действие` (например, «Промыть фильтр №2»).
4. Система создаёт запись «Предиктивный инцидент» со статусом «Новый» и блокирует возможность закрытия партии без проверки.
5. Система отправляет Push-уведомление и SMS главному технологу.
6. Технолог открывает инцидент в системе, изучает график трендов и рекомендацию.
7. Технолог выполняет действие на производстве и нажимает в системе кнопку «Действие выполнено, риск устранён».
8. Система переводит инцидент в статус «Закрыт», логирует действие и разрешает дальнейшее движение партии.

### Альтернативный поток 3а. Ложное срабатывание (False Positive)

- В шаге 6 технолог проверяет показатели и видит, что они в норме, а рекомендация неприменима.
- Технолог выбирает опцию «Ложное срабатывание» и указывает причину.
- Система переводит инцидент в статус «Отклонён», а данные инцидента отправляются в ML-Модуль как размеченный датасет для дообучения модели (Feedback Loop).

### Постусловие

- Инцидент закрыт (успех либо ложное срабатывание); факт обработки зафиксирован и, при необходимости, использован как обучающий пример для ML-модели.

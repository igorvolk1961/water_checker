# AquaPredict LIMS — Требования к пользовательскому интерфейсу (UI Requirements)

**Версия:** 0.3. **Статус:** детализация (C-03) синхронизирована с правкой ведущего от 2026-10-12: модель состояний инцидента — по доменной модели (`06_domain_model.md`), SCR-09 ↔ UC8/EPIC-14, LGL-01/02/07 в редакции ведущего.
**Основа:** карта экранов из `requirements/functional_requirements.md` (v1.1, раздел 2), FR-01…FR-16, NFR-1…NFR-7, LGL-01…14, KPI (`kpi.md`), TEL/LAB-перечни (`requirements/measured_parameters.md`).
**Термины** — строго по `02_glossary.md`.
**Вилка A/B:** разрешена — вариант A (надстройка) подтверждён ведущим 2026-10-12 (Gate 1). Все 12 экранов детализированы; SCR-03/04/05 — read-only представления поверх данных 1С.

## 1. Соглашение об ID

- `SCR-xx` — экран (унаследован из FR-скелета, не меняется);
- `UI-xx` — сквозное требование к UI;
- `UI-SCR-xx.n` — детальное требование внутри экрана;
- `ST-xx` — состояние экрана/сущности.

## 2. Сквозные требования к UI (UI-01…UI-08)

| ID | Требование | Источник |
| --- | --- | --- |
| UI-01 | Критическое предупреждение (риск > 80 % при текущем значении рабочей точки): красное выделение, звуковой сигнал, **явное подтверждение ознакомления** до продолжения работы на экране | NFR-4, FR-05 |
| UI-02 | Рабочая точка (порог критического алерта) нигде не захардкожена в UI: экраны показывают **текущее значение** и признак «утверждено эксплуатантом» | LGL-09, FR-05, FR-13 |
| UI-03 | Дисклеймер о вероятностном характере прогноза — на каждом экране с прогнозом; формулировка и место — единые (компонент) | LGL-09 |
| UI-04 | Дисклеймер HITL «система рекомендует, решение и действие — за персоналом» — на экранах с рекомендациями и задачами КА | LGL-04, FR-06 |
| UI-05 | Предупреждение против automation bias: периодическое напоминание и/или выборочный контроль подтверждений (механизм — FR-14) | LGL-14 |
| UI-06 | Все данные «БИТ.Лаборатории» (пробы, результаты, протоколы, статусы) отображаются **только для чтения**; действия ввода/валидации/подписи в AquaPredict отсутствуют — ссылка/переход в 1С | FR-08, LGL-02, LGL-11 |
| UI-07 | Аудит-след: UI-действия фиксируются с различением «рекомендация системы» / «решение человека» / «фактическое действие» | LGL-10, FR-14 |
| UI-08 | Ошибка/деградация синхронизации с 1С — единый индикатор доступности интеграции в шапке + баннер на затронутых экранах с временем последней успешной синхронизации (NFR-6: очередь/пакетирование, не блокировать UI) | FR-15, NFR-6 |

## 3. Навигация и роли

- Вход в веб-консоль AquaPredict — по ролям (RBAC, FR-14): главный технолог (ГТ), оператор линии (ОЛ — объём доступа — открытый вопрос 2), лаборант (ЛБ — в 1С; в веб-консоли — только SCR-05 read-only, объём — открытый вопрос 2/3), руководитель лаборатории (РЛ), ML-инженер (DS), администратор (АДМ), инженер КИПиА.
- Основной маршрут демонстрации: **SCR-01 → SCR-02 → SCR-03 (каркас)** — поток UC2 → UC3/UC4.
- Переходы: SCR-01 → SCR-02 (клик по инциденту); SCR-02 → SCR-03 (задача КА/отбора); SCR-01 → SCR-04 (каркас, партия); SCR-09 и SCR-10 — из главного меню по роли; SCR-11 — только АДМ; SCR-06/07 — DS/ГТ/РЛ.
- Push/SMS (SCR-12) — вне веб-консоли, ведут в веб-консоль глубокими ссылками (алерт → SCR-02, задание → SCR-03).

## 4. Детализация экранов, не зависящих от вилки A/B

### SCR-01. Дашборд технолога: линии, активные алерты, риски (Must)

Роли: ГТ, ОЛ (объём — открытый вопрос 2). UC1, UC2; FR-01, FR-03–FR-05.

- **UI-SCR-01.1** Состав зон: (а) список линий розлива со статусом наблюдаемых партий; (б) лента активных алертов с сортировкой по уровню риска и времени; (в) сводка бюджетов (алертов за час / лимит 10 — NFR-5); (г) индикатор синхронизации с 1С (UI-08).
- **UI-SCR-01.2** Каждый алерт: партия, параметр риска (TEL-код), вероятность, горизонт, рекомендованное действие (событие `RiskAlert`, FR-05); критический уровень — по UI-01.
- **UI-SCR-01.3** Подтверждение ознакомления с критическим алертом фиксируется (кто, когда) и попадает в аудит (UI-07); без подтверждения — повторный сигнал (звук/бейдж).
- **UI-SCR-01.4** Источник фазы скоринга помечен (Слой 1 правила / Слой 2 ML — термины `kpi.md` §2); для ML — дисклеймер UI-03.
- **UI-SCR-01.5** Состояния алерта на дашборде: Новый → Ознакомлен → В работе (инцидент открыт) → Закрыт; связь «алерт → карточка инцидента SCR-02» — один клик.
- Допустимая задержка обновления: ≤ 5 с от генерации алерта (NFR-1).

### SCR-02. Карточка предиктивного инцидента (Must)

Роли: ГТ. UC2, UC3; FR-06, FR-12. Ядро демонстрации.

- **UI-SCR-02.1** Состав: заголовок инцидента (партия, параметр, вероятность, горизонт); тренды телеметрии по связанным TEL-параметрам (окно до 2 ч); рекомендованные шаги КА; блок вердикта; журнал событий инцидента.
- **UI-SCR-02.2** Вердикт по инциденту — отдельная сущность: [Подтверждён / Ложное срабатывание] + причина (FR-06); результат КА [Выполнено / Отменено] отображается отдельно и не смешивается с вердиктом (устранение дефекта US-05.1).
- **UI-SCR-02.3** Действия ГТ: подтвердить ознакомление (UI-01); назначить/создать задачу КА в 1С (FR-06); зафиксировать вердикт (FR-12); ссылка на задание внепланового отбора (SCR-03-каркас).
- **UI-SCR-02.4** Дисклеймеры: UI-03 (вероятностный прогноз), UI-04 (HITL), предупреждение «ML-алерт не является основанием для браковки партии» (LGL-11).
- **UI-SCR-02.5** Состояния инцидента (ST-инцидент, по доменной модели ведущего `06_domain_model.md`): Новый → Подтверждён / Ложный_алерт → Закрыт; блокировка закрытия партии в 1С без проверки инцидента отображается как статус (FR-01.4).
- **UI-SCR-02.6** Вердикт «Ложное срабатывание» требует указания причины из справочника (свободный текст — дополнительно); вердикт уходит в разметку (FR-11/FR-12) с пометкой «прокси-метка».

### SCR-06. Экран «Метрики модели» (Should)

Роли: DS, ГТ, РЛ. FR-13; данные `kpi.md` §2–§3 (точка I-10); LGL-09.

- **UI-SCR-06.1** Разделы: (а) пофазные цели и текущие значения Recall / Precision / FPR / FNR / F1 (раздельно Фаза 1 / Фаза 2, рядом колонка Baseline); (б) горизонт (Lead time) и бюджет алертов (текущее потребление / 10 в час); (в) дрейф данных (Data Drift) и статус модели (Shadow / Advisor); (г) рабочая точка.
- **UI-SCR-06.2** Рабочая точка: порог алертинга, принятые остаточные FPR/FNR, признак «утверждено эксплуатантом» и дата утверждения (LGL-09); изменение порога отсюда не выполняется — ссылка на SCR-11 (право АДМ/эксплуатанта).
- **UI-SCR-06.3** Baseline-метрики и цели — только чтение; редактирование целевых KPI — вне UI (документ `kpi.md`, версия).
- **UI-SCR-06.4** Дисклеймер вероятностного характера и «прокси»-статуса бизнес-KPI (контрафактуальность, `kpi.md` §5) — в подвале разделов.

### SCR-07. MLOps-модуль (Should)

Роли: DS. UC6; FR-11, FR-12; LGL-13.

- **UI-SCR-07.1** Разделы: датасеты (объём, дата, источник меток); очередь разметки; карантин конфликтов разметки; версии моделей; история переобучений.
- **UI-SCR-07.2** Уведомление «Накоплено N новых размеченных примеров» (поток UC6, шаг 3) — бейдж с переходом к датасету.
- **UI-SCR-07.3** Запуск переобучения: выбор датасета → запуск пайплайна → сравнение метрик новой версии с рабочей (таблица) → [Утвердить и развернуть / Отменить]; отмена при ухудшении (поток 6а) фиксируется с флагом «Требуется проверка аномалий» и уведомлением DS + ГТ.
- **UI-SCR-07.4** Карантин: пример не используется в обучении до разрешения; разрешение — выбор приоритетного источника (лабораторный протокол приоритетнее вердикта технолога, FR-11) с фиксацией решения (поток 6б).
- **UI-SCR-07.5** Приоритет источников меток отображается явно: «лабораторный протокол > вердикт технолога» (Приоритет источника разметки, FR-11/FR-12).

### SCR-08. Cold Start (Must, Этап 0)

Роли: DS, ГТ. UC7; FR-10.

- **UI-SCR-08.1** Мастер из шагов: импорт архива (SCADA Historian CSV / OPC-UA HDA, лабораторные журналы) → отчёт о качестве импорта → матчинг «срез телеметрии за окно (2 ч) → проба» → отчёт о матчинге (доля успешных ≥ 90 % — системный KPI, `kpi.md` §4) → обучение Baseline-профиля → подтверждение ГТ «Эталонный».
- **UI-SCR-08.2** Отчёт о матчинге: доля сопоставленных проб, список несопоставленных с причинами; повторный запуск матчаинга на подмножестве.
- **UI-SCR-08.3** Подтверждение Baseline-профиля как «Эталонный» — действие ГТ с фиксацией в аудите (UI-07); до подтверждения — статус «Черновик».
- **UI-SCR-08.4** Альтернативный поток 7а (недостаток архива): предложение Pre-training на синтетике цифрового двойника и продление калибровки — как явный шаг мастера с пояснением.
- **UI-SCR-08.5** Статус фазы внедрения и критерии перехода (§4 `10_cold_start_and_archival_data.md`) — индикатор «Фаза 0 → …» (для движка — Слой 1/Слой 2; терминология — см. G-5 ревью, ожидаем правку глоссария).

### SCR-09. Мониторинг канала телеметрии (Must)

Роли: инженер КИПиА. UC8; FR-16; NFR-2; эпик EPIC-14.

- **UI-SCR-09.1** Список датчиков TEL-01…TEL-13 со статусами: Норма / Нет данных / «Заморожено» (значение не меняется N мин) / Вне физического диапазона / Задержка потока; последняя валидная отметка времени.
- **UI-SCR-09.2** Статус буфера IoT-шлюза: заполнение, режим буферизации при потере связи, оценка глубины (до 2 ч — NFR-2), прогресс автосинхронизации после восстановления.
- **UI-SCR-09.3** Диагностика аномалий потока: пропуски, «замороженные» значения, выход за физически возможные диапазоны (FR-16) — события с историей за период.
- **UI-SCR-09.4** Уведомления КИПиА о деградации канала (канал — SCR-12); связь с достоверностью скоринга: пометка на SCR-01/SCR-02, если инцидент рассчитан по деградировавшему каналу.

### SCR-10. Аудит-лог (Must)

Роли: РЛ, АДМ. FR-14; LGL-03, LGL-10.

- **UI-SCR-10.1** Единый журнал с фильтрами: период, роль, пользователь, сущность (инцидент/задача/партия), источник события («AquaPredict» / «1С»), категория («рекомендация системы» / «решение человека» / «фактическое действие»).
- **UI-SCR-10.2** Запись: кто, когда, что, над какой сущностью, источник (система/человек/действие в 1С), результат; неизменяемость записей (только чтение в UI).
- **UI-SCR-10.3** Выгрузка журнала (CSV) для выборочного контроля (LGL-14) — право РЛ/АДМ, выгрузка фиксируется в журнале.
- **UI-SCR-10.4** ПДн в записях минимизированы (LGL-05); маскирование персональных данных в представлении по умолчанию, раскрытие — по праву и с фиксацией.

### SCR-11. Администрирование (Must)

Роли: АДМ. FR-14, FR-15; LGL-05, LGL-09, NFR-5.

- **UI-SCR-11.1** Разделы: пользователи и роли (RBAC: ГТ, ОЛ, ЛБ, РЛ, DS, АДМ, КИПиА); справочник нормативов (СанПиН 1.2.3685-21 / ГОСТ 32220-2013); рабочая точка; настройки интеграции 1С; параметры ПДн.
- **UI-SCR-11.2** Рабочая точка: текущий порог критического алерта, история изменений (кто/когда/было/стало), признак утверждения эксплуатантом (LGL-09); изменение — только АДМ с подтверждением и записью в аудит; NFR-4 автоматически применяется к текущему значению.
- **UI-SCR-11.3** Справочник нормативов: версия/дата вступления; изменение — только с комментарием и в аудите; отображение «источник: справочник» на SCR-04-каркасе (сверка результатов — подсветка, решение — в 1С, LGL-11).
- **UI-SCR-11.4** Настройки интеграции 1С: endpoint OData/HTTP-сервисов, лимит ≤ 60 запросов/мин (NFR-6, guardrail), размер пакета, состояние очереди; изменение — АДМ, после согласования с администратором 1С заказчика.
- **UI-SCR-11.5** Параметры ПДн: состав хранимых ПДн сотрудников, сроки, маскирование (LGL-05); настройки уведомлений SCR-12 (каналы ГТ: push/SMS).

### SCR-12. Push/SMS-уведомления (Must)

Роли: ГТ (получатель), ЛБ — только средства 1С (открытый вопрос 3). UC2, UC4; FR-05; NFR-1.

- **UI-SCR-12.1** Содержимое уведомления: тип (критический алерт / задание КА / задание внепланового отбора / деградация канала КИПиА), партия, параметр, вероятность, горизонт; глубокая ссылка на SCR-02/SCR-03/SCR-09.
- **UI-SCR-12.2** Бюджет алертов распространяется на уведомления: приоритизация и подавление дублей (NFR-5); признак «подавлено как дубль» виден в истории уведомлений.
- **UI-SCR-12.3** История уведомлений пользователя с статусы доставки (отправлено/доставлено/ошибка) — чтение; настройка каналов — в SCR-11.
- **UI-SCR-12.4** Уведомление лаборанту о задании отбора — штатными механизмами 1С (задание создаётся в 1С, FR-07); AquaPredict не дублирует канал лаборанта (до решения открытого вопроса 2).

## 5. Экраны, детализированные после подтверждения варианта A (Gate 1)

### SCR-03. Задачи на КА и отбор: представление поверх задач 1С (Must)

Роли: ГТ, ОЛ (объём — открытый вопрос 2), ЛБ. UC3, UC4; FR-06, FR-07, FR-08; LGL-10.

- **UI-SCR-03.1** Состав: список задач двух типов (задача КА, задание внепланового отбора) с фильтрами по партии, статусу, исполнителю, приоритету; источник данных — 1С (чтение OData), представление — read-only (UI-06).
- **UI-SCR-03.2** Строка задачи: тип, партия, ссылка на инцидент (SCR-02) / задание отбора, приоритет («Срочно» — выделение), исполнитель, статус из 1С (ST-03), время создания/выполнения, просрочка.
- **UI-SCR-03.3** Карточка задачи: рекомендованные шаги (созданы системой), история статусов (создана → назначена → выполнена), приложения (фото/комментарий — добавляются в 1С, отображаются read-only), различение источника события (LGL-10, UI-07).
- **UI-SCR-03.4** Действия из веб-консоли — ограничены: просмотр, переход в карточку инцидента, ссылка/переход в 1С для работы с задачей; при подтверждении доступа ОЛ (открытый вопрос 2) — те же ограничения.
- **UI-SCR-03.5** Состояние синхронизации: если статусы задач не читаются (ST-07 Ошибка) — баннер UI-08, список замораживается с временем последней успешной синхронизации.
- **UI-SCR-03.6** Уведомления по задачам — средства 1С (FR-06/FR-07); AquaPredict не дублирует канал (SCR-12.4).

### SCR-04. Аналитика по партии (Must)

Роли: ГТ, РЛ, DS. UC5 (вариант A); FR-08; LGL-11.

- **UI-SCR-04.1** Состав: выбор партии (из 1С) → график телеметрии по TEL-параметрам с наложением лабораторных результатов LAB-01…LAB-16 на временную ось (связка «проба → срез за окно 2 ч», FR-08); список инцидентов и задач по партии.
- **UI-SCR-04.2** Сверка с нормативами: значения показателей подсвечиваются против справочника (СанПиН 1.2.3685-21 / ГОСТ 32220-2013, версия и дата — из SCR-11.3); подсветка — **информационная**: решение о несоответствии остаётся в контуре 1С/лаборатории (LGL-11, UI-06).
- **UI-SCR-04.3** Карточка показателя: значение, норматив (диапазон/ПДК для категории воды), статус [Норма / Превышение — информационно], ссылка на протокол испытаний в 1С.
- **UI-SCR-04.4** Прогнозный контур (для целевых показателей из `kpi.md` §3): расчётный риск по партии, Слой (правила/ML), дисклеймер UI-03; ML-риск не помечает партию как брак (LGL-11).
- **UI-SCR-04.5** Экспорт среза (CSV) для DS — право DS/РЛ, фиксируется в аудите (UI-07).

### SCR-05. Статусы протоколов и ФГИС-выгрузки (Should)

Роли: РЛ, ЛБ. UC5 (вариант A); FR-09; LGL-01, LGL-02, LGL-07.

- **UI-SCR-05.1** Состав: список протоколов по партиям (чтение из 1С) со статусами валидации; отдельная колонка — статус ФГИС-выгрузки и UUID зарегистрированной записи (LGL-01 в редакции ведущего: выгрузка — штатный контур 1С, не дублируется).
- **UI-SCR-05.2** Статусы протокола: В работе → Валидирован → Подписан (ЭП, контур 1С) → Выгружен во ФГИС → UUID получен; ЭП и подписант отображаются read-only, ЭП и подписант — вне проекта (контур 1С, LGL-02 в редакции ведущего).
- **UI-SCR-05.3** Сопроводительные данные инцидента, переданные системой в 1С для выгрузки (телеметрия, КА — объём по открытому вопросу 1, FR-09.2): признак «передано» с датой; неполнота — предупреждение РЛ.
- **UI-SCR-05.4** Запреты (LGL-07): неподписанный/невалидированный протокол **не отображается как «отправляемый»** — статус строго читается из 1С; кнопок «выгрузить»/«подписать» в AquaPredict нет (UI-06).
- **UI-SCR-05.5** Ошибка/отказ выгрузки со стороны ФГИС (если 1С передаёт статус ошибки) отображается для РЛ с рекомендацией обратиться в контур 1С; AquaPredict повторную отправку не выполняет.

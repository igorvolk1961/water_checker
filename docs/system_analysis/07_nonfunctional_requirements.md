# AquaPredict LIMS — Нефункциональные требования (NFR)

Для IoT/ML-систем нефункциональные требования критически важны и показывают зрелость аналитика.

1. **Производительность (Performance).** Задержка (latency) между получением данных с датчика и генерацией предиктивного алерта не должна превышать 5 секунд.
2. **Надёжность (Reliability).** Система должна поддерживать буферизацию данных с датчиков на стороне шлюза в течение до 2 часов при потере связи с центральным сервером, с последующей автоматической синхронизацией.
3. **Интегрируемость (Interoperability).** Система должна поддерживать приём данных по стандартным промышленным протоколам OPC-UA и MQTT.
4. **Удобство использования (Usability).** Критическое предупреждение (уровень риска выше настроенного **порога алертинга / рабочей точки**) должно визуально выделяться на дашборде технолога (красный цвет, звуковой сигнал) и требовать явного подтверждения ознакомления. Порог — конфигурируемый параметр (не константа).

## Guardrails (ограничения-предохранители)

5. **Бюджет алертов (Alert Budget).** Система не должна генерировать более **10 алертов в час** на линию; при превышении — приоритизация и подавление дублей (защита от alert fatigue и снижения доверия технолога). Связано с FPR (`kpi.md`).
6. **Нагрузка на «БИТ.Лабораторию» (1С).** Обмен через OData/HTTP не должен превышать **≤ 60 запросов в минуту** к серверу 1С; пиковые операции — пакетирование и очередь запросов. Согласуется с администратором 1С.
7. **Отсутствие обратного управления.** Система не пишет команды в ПЛК/SCADA (Out-of-Scope); любые записи — только в «БИТ.Лабораторию» (задачи, комментарии, статусы через штатные сервисы).

> Значения guardrails (10 алертов/час, ≤ 60 запросов/мин) — предварительные допущения, подтверждаются с заказчиком и владельцем 1С.

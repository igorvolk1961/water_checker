# Sequence v1 — UC8: мониторинг источников телеметрии (КИПиА)

**Версия:** 0.1 (C-05, дополнение). Показывает цикл «аномалия → диагностика → восстановление → возврат достоверности данных в скоринг». Термины — `02_glossary.md`; процесс — BPMN UC8 (`bpmn_uc8_telemetry_monitoring.md`); состояния — FR-16.

```mermaid
sequenceDiagram
    autonumber
    participant ДТ as Датчики (OPC-UA)
    participant ШЛ as IoT-шлюз
    participant КН as Контроль потока (система)
    participant СК as Риск-скоринг
    participant КИП as Инженер КИПиА

    loop непрерывно (UC8, FR-16.1)
        ДТ->>ШЛ: показания TEL-01…TEL-13
        ШЛ->>КН: поток телеметрии (буфер ≤ 2 ч при потере связи, NFR-2)
        КН->>КН: проверка целостности: пропуски,<br/>«замороженные» значения, рассинхронизация времени,<br/>выход за физический диапазон
    end

    alt аномалия обнаружена
        КН->>КИП: диагностическое уведомление (канал — SCR-12,<br/>событие с историей на SCR-09)
        КН->>СК: пометка достоверности канала [Деградировал]
        СК->>СК: инциденты/алерты по этим данным —<br/>признак пониженной достоверности (FR-16.4, SCR-01/02)
        КИП->>КИП: устранение неисправности (вне систем, HITL)
        КИП->>КН: подтверждение восстановления
        КН->>ШЛ: досинхронизация буфера (без дублей, NFR-2/FR-01.3)
        КН->>СК: канал [Норма] — возобновление использования<br/>данных источника в риск-скоринге
    else поток в норме
        КН->>КН: продолжение мониторинга —<br/>статусы датчиков и буфера на SCR-09
    end
```

## Замечания

- Достоверность телеметрии — условие корректности прогноза: FR-03/FR-04 потребляют только достоверные данные (связь UC8 ↔ UC2).
- Уведомление КИПиА не расходует бюджет алертов линии (NFR-5 — бюджет для предиктивных алертов; диагностические события — отдельный канал; уточнить в C-08 при ревью).

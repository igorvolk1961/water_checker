## Слайд 2. Проблема

- LIMS работают **реактивно**: отклонение качества выявляется **постфактум** (партия уже произведена).
- Телеметрия линии (давление, озон, мутность, температура…) **не используется** для упреждающего контроля.
- Итог: прямые потери (утилизация) и репутационные риски.

> Заметка: подчеркнуть разрыв — данные есть, пользы нет. Цифры проблемы — допущение (партия ~6000 л, брак 3–5 %, ~300 тыс ₽/мес).

---

## Слайд 3. Решение и идея

- **Цифровой ассистент технолога:** предсказывает отклонения и **подсказывает действие**.
- **За 2 часа до, а не после выпуска партии.**
- Принцип **HITL** — система рекомендует, решение принимает человек.
- Ранний сигнал → корректирующее действие → партия не становится браком.

> Заметка: это ключевой слайд — «почему мы». Не углубляться в технику.

## Слайд 11. Интеграция с 1С и «мост»

- Интеграция: чтение по **OData**, запись задач/вердиктов по **HTTP**; ≤ 60 зап./мин; идемпотентность; очередь.
- Доступ к реальному API заказчика **не предоставлен**; публичной техдокументации нет → имена **условные** (В-7.3).
- При появлении доступа реализуется **мост (adapter/ACL)**, маппящий реальные сущности на наши модели.

> Заметка: честно про доступ; показать, что архитектурно это предусмотрено.

## Слайд 12. Право и ответственность (стохастичность ИИ)

- Нормативы: ТР ЕАЭС 044/2017, СанПиН, ГОСТ, ФЗ-152/63, ФГИС.

- Точность — целевые метрики, **не гарантия**; браковка — только по лабораторному контролю и ЭП.

## Слайд 13. Экономика (честно)

- CAPEX: ПО ≈ 7,09 + оборудование ≈ 2,28 → ≈ 9,37 млн ₽; с резервом ≈ **11,2 млн ₽**; OPEX ≈ 1,2–2,4 млн ₽/год.

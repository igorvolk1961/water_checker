# BPMN v1 — UC8: Мониторинг источников телеметрии (КИПиА)
> **Канонический BPMN:** `bpmn/uc8.bpmn` (BPMN 2.0, bpmn.io / Camunda Modeler) · схема: `bpmn/uc8.svg`


**Версия:** 1.0 (C-04, финализация R-8; UC8 добавлен ведущим 2026-10-12 — закрытие потребности стейкхолдера «Инженер КИПиА», находка G-3 ревью). FR-16; эпик EPIC-14; NFR-2. Диагностические события КИПиА — отдельный канал, бюджет предиктивных алертов (NFR-5, 10/час) не расходуют; подавление дублей — до создания инцидента (решение В-6.1).

## Дорожки

1. **Система AquaPredict** (фоновый контроль)
2. **Инженер КИПиА**

## Поток

| № | Дорожка | Шаг / элемент | Тип |
| --- | --- | --- | --- |
| 1 | Система | Непрерывная проверка доступности датчиков (OPC-UA) и целостности потока: пропуски отметок, «замороженные» значения, рассинхронизация времени, выход за физические границы значений (FR-16.1, FR-02.4) | задача |
| 2 | Система | Аномалия обнаружена? | шлюз |
| — | — | **Нет** → продолжение мониторинга; статусы датчиков и буфера — на SCR-09 | — |
| 3 | Система | Диагностическое уведомление инженеру КИПиА (канал — SCR-12); пометка достоверности канала | задача (FR-16.3) |
| 4 | Система | Скоринг по данным деградировавшего канала помечается признаком пониженной достоверности (SCR-01/SCR-02) | задача (FR-16.4) |
| 5 | КИПиА | Устранение неисправности (вне системы) и подтверждение восстановления | задача (HITL) |
| 6 | Система | Досинхронизация буфера (≤ 2 ч, NFR-2); возобновление использования данных источника в риск-скоринге | конец |

## Связи

- Достоверность телеметрии — условие корректности прогноза: FR-03/FR-04 потребляют только достоверные данные.
- Статус буфера шлюза — SCR-09.2 (FR-16.2).

## Для бэклога (I-6; эпик EPIC-14)

Кандидаты в истории: контроль доступности/целостности потока; диагностика и уведомления КИПиА; пометка достоверности для скоринга; экран мониторинга SCR-09; подтверждение восстановления.

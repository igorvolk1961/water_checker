# AquaPredict — Руководство администратора

**Версия:** 1.0. **Статус:** документ поставки (ТЗ §5.7). **Для кого:** администратор AquaPredict (АДМ). Экран: SCR-11; аудит — SCR-10.

## 1. Роли и доступ (RBAC)

1. Заведите пользователей и назначьте роли: главный технолог, инженер КИПиА, руководитель лаборатории, ML-инженер, администратор. Матрица прав «роль × экран» — `requirements/ui_requirements.md` §3.
2. Принцип минимальных прав: не выдавайте роль «Администратор» технологам; оператор линии и лаборант в консоль не входят (работают в 1С — OQ-03/04).
3. Аутентификация: интеграция с AD/LDAP (NFR-8) или локальные учётные записи (фолбэк). При увольнении сотрудника — деактивация УЗ в тот же день.

## 2. Рабочая точка (порог критического алерта)

1. Текущий порог, остаточные FPR/FNR и признак утверждения эксплуатантом — на экране «Администрирование».
2. Изменение порога: кнопка «Изменить порог» (только роль АДМ) → **изменение должно быть утверждено эксплуатантом** — это управленческое решение о принятом остаточном риске (LGL-09). Каждое изменение: было/стало, дата, кто — в истории и в аудите.
3. Помните: поведение интерфейса (NFR-4: красное выделение, звук, подтверждение) привязано к текущему значению порога автоматически.

## 3. Справочник нормативов

1. Актуализируйте нормативы (СанПиН 1.2.3685-21, ГОСТ 32220-2013) при изменении редакций: значение, версия, дата, комментарий.
2. Изменение фиксируется в аудите; экран «Аналитика по партии» показывает версию справочника рядом со сверкой.

## 4. Интеграция с «БИТ:LIMS» (1С)

1. Параметры: endpoints OData/HTTP, лимит ≤ 60 запросов/мин (NFR-6), размер пакета. Настройка HTTP-сервисов **на стороне 1С — администратор 1С заказчика**; изменения контракта — через версии (`requirements/integration_contract_1c.md`, LGL-R3).
2. Мониторинг: состояние очереди на SCR-11; при деградации — режим «очередь/ошибка» (ST-07). Очередь персистентна (Redis, AOF) — при рестарте системы записи не теряются.
3. Действия при ошибке синхронизации: проверить доступность 1С и учётные данные; не отключать систему — приём телеметрии и скоринг продолжаются, записи ждут в очереди.

## 5. Персональные данные (LGL-05/06)

1. Хранится минимум: ФИО исполнителей корректирующих действий, логины. Маскирование в представлениях по умолчанию; раскрытие — по праву и фиксируется в аудите.
2. Срок хранения данных системы — **1 год** (решение заказчика, LGL-06).
3. Обработка ПДн — на основании договора; вопросы — к юристу заказчика/исполнителя.

## 6. Резервное копирование и восстановление

1. RTO ≤ 4 ч, RPO ≤ 15 мин (NFR-10/11): настройте расписание резервного копирования PostgreSQL (включая телеметрию с партиционированием) и конфигурации; проверяйте восстановление на тестовом контуре не реже 1 раза в квартал.
2. Очередь исходящих в Redis — персистентность AOF (решение Ведущего, ADR-02); режимы AOF/RDB и расписание снапшотов — по регламенту эксплуатации заказчика.

## 7. Диагностика и типовые ситуации

| Ситуация | Где смотреть | Действие |
| --- | --- | --- |
| «Ошибка синхронизации с 1С» | SCR-11 §4, SCR-10 | Проверить доступность/учётные данные; задачи копятся в очереди — не теряются |
| Датчик «Нет данных» / «Заморожено» | SCR-09 | Передать инженеру КИПиА; инциденты по каналу помечены менее достоверными |
| Деградация метрик / дрейф | SCR-06, SCR-07 | Уведомить ML-инженера; развёртывание новой версии — только осознанно |
| «Мёртвая» очередь записей | SCR-11, уведомление | Разобрать причину, переотправить после восстановления 1С (`domain_events.md` §0) |
| Жалоба на «много алертов» | SCR-01 бюджет, SCR-06 FPR | Проверить потребление бюджета; при необходимости — согласовать изменение рабочей точки с эксплуатантом |

## 8. Неизменяемый аудит

Аудит-лог (SCR-10) содержит все рекомендации системы, решения персонала и фактические действия с различением источников. **Записи не редактируются и не удаляются.** Выгрузка CSV — ваша функция; сама выгрузка фиксируется в журнале. Используйте выгрузку для периодического выборочного контроля решений (LGL-14) — механизм против «слепого доверия системе».

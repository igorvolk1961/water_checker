# AquaPredict — Требования к оборудованию и инфраструктуре (Hardware & Infrastructure Requirements)

Обоснование необходимого оборудования и инфраструктуры для работы системы (вариант A — надстройка над «БИТ.Лаборатория»). Источники требований: FR (`requirements/functional_requirements.md`), NFR (`07_nonfunctional_requirements.md`), параметры (`requirements/measured_parameters.md`), глоссарий (`02_glossary.md` §7), допущения (`assumptions_log.md`).

## 1. Состав по зонам

### 1.1 Средства измерений (телеметрия) — TEL-01…TEL-13

| Группа | Оборудование | Требование | Обоснование |
| --- | --- | --- | --- |
| Давление | Датчики давления до/после мембраны обратного осмоса (TEL-01/02) | диапазон по узлу, погрешность ≤ 0,5 % ВПИ, OPC-UA/MQTT, ≥ 1 изм./мин | FR-02.1, NFR-3, TEL-01/02 |
| Перепад | Перепад на фильтре (TEL-03, расчётный) | вычисляется из TEL-01/02 | FR-03.1 |
| Расход | Расходомер пермеата (TEL-04) | ≥ 1 изм./мин | FR-02.1 |
| Обеззараживание | Анализатор остаточного озона (TEL-05), датчик дозы УФ (TEL-11) | ≥ 1 изм./мин, ресурс/калибровка | FR-02.1, FR-03.1 |
| Качество (inline) | Мутномер (TEL-06), pH-метр (TEL-09), кондуктометр (TEL-10) | ≥ 1 изм./мин, промывка/калибровка | FR-02.1, `measured_parameters.md` |
| Температура | Датчики температуры воды и в цеху (TEL-07/08) | ≥ 1 изм./мин | FR-02.1 |
| Контекст | Счётчик объёма/скорости розлива (TEL-12), сигнал режима run/stop/CIP (TEL-13) | событийный/дискретный | FR-02.1 |

Общие требования к датчикам: промышленное исполнение и санитарные нормы для пищевого производства (материалы контакта, мойка CIP), калибровка по регламенту, вывод по стандартному протоколу (OPC-UA/MQTT). Часть датчиков может уже присутствовать на линии (см. §4).

### 1.2 IoT-шлюз (сбор и буферизация)

- Промышленный шлюз с ролью OPC-UA-клиента (сбор с датчиков/SCADA) и MQTT-клиента (передача в систему, TLS).
- **Буферизация при потере связи ≥ 2 ч** с автосинхронизацией в исходном порядке — NFR-2 (FR-02.3).
- Локальное энергонезависимое хранилище под буфер, синхронизация времени (NTP).
- Исполнение по условиям цеха (IP-защита, питание), резерв питания/ИБП.

### 1.3 Вычислительная инфраструктура (серверы/облако)

| Компонент | Назначение | Требование (пример) |
| --- | --- | --- |
| App-сервер | FastAPI/uvicorn (веб-консоль, API) | Linux, 4 vCPU, 8–16 ГБ RAM |
| Worker | Фоновая очередь (Redis): ретраи синхронизации, переобучение, дрейф | 2–4 vCPU, 4–8 ГБ RAM |
| БД | PostgreSQL (партии, инциденты, КА, вердикты, аудит); миграции Alembic | 2–4 vCPU, 8–16 ГБ RAM, SSD |
| Телеметрия (time-series) | PostgreSQL с партиционированием или TimescaleDB; retention 1 год (LGL-06) | SSD, см. сайзинг §3 |
| Redis | Очередь задач/кэш | 1–2 vCPU, 2–4 ГБ RAM |
| ML | обучение Baseline/Слоя 2 (scikit-learn), Feature Store, реестр моделей | CPU достаточно; GPU — опционально |

Развёртывание: контейнеризация (Docker), оркестрация — опционально; окружения Dev/Test/Prod (`plans/backlog_implementation_plan.md` §5).

### 1.4 Сеть и безопасность

- Выделенный сегмент промышленной сети (OT) с межсетевым экраном; доступ системы к датчикам/шлюзу.
- Защищённые каналы: TLS для MQTT/HTTP; VPN/шлюз для доступа к серверу 1С.
- Синхронизация времени (NTP) на всех узлах (важно для матчинга, `10_cold_start_and_archival_data.md`).
- **Guardrail к 1С — ≤ 60 запросов/мин** (NFR-6): очередь/пакетирование на app-сервере.
- Резервирование каналов и БД (backup), мониторинг доступности (SLA ≥ 99 %, `kpi.md` §4).

### 1.5 Клиентские АРМ

- **АРМ технолога** — рабочая станция с браузером для веб-консоли (SCR-01…12).
- **Терминал/планшет КИПиА** — диагностика канала и уведомления (UC8, SCR-09/12).
- Лаборант работает в «БИТ.Лаборатории» — **отдельные АРМ не требуются** (вариант A, OQ-04).

### 1.6 Существующие источники данных (не создаются проектом)

- SCADA Historian заказчика — шаг ≤ 1 мин, хранение ≥ 3 лет (ASM-01) для Cold Start/ETL.
- Сервер «1С:БИТ.Лаборатория» (приложения + БД) — интеграция OData/HTTP (FR-15).

## 2. Обоснование (почему именно так)

- Требования к датчикам и частоте вытекают из **NFR-1/3** (latency ≤ 5 с, частота ≥ 1/мин) и перечня TEL (`measured_parameters.md`).
- Шлюз с буферизацией — прямое следствие **NFR-2** (≤ 2 ч офлайн).
- Серверы/БД/Redis — из технологического стека (`architecture_stack.md`) и нефункциональных требований (доступность, retention).
- Guardrail ≤ 60 req/min (NFR-6) обосновывает очередь к 1С.

## 3. Сайзинг (оценочно, допущения)

- **Телеметрия:** 13 тегов × 1 изм./мин = 780/час ≈ **18 720 записей/сутки** ≈ 6,8 млн/год.
- Объём: ~24–32 байт/точка → **≈ 160–220 МБ/год** «сырых»; с индексами/служебными данными ×2–3 → **≈ 0,3–0,7 ГБ/год**. При retention 1 год — **< 1 ГБ** (плюс БД приложения).
- **API:** до ~20 одновременных пользователей (допущение), latency ≤ 5 с (NFR-1).
- **ML:** периодическое обучение Baseline/Слоя 2 — ресурсоёмкость умеренная (scikit-learn, CPU).
- **Итог:** достаточно 1 сервер приложений + 1 сервер БД (или ВМ) + Redis; GPU не требуется. Точные параметры уточняются при обследовании.

## 4. Допущения и риски

- Датчики TEL-01…13 частично или полностью **уже установлены** на линии; при отсутствии — дооснащение силами заказчика (см. `assumptions_log.md`, ASM-16).
- Совместимость существующего оборудования с OPC-UA/MQTT подтверждается при обследовании (риск PRJ-01).
- Санитарные требования к монтажу датчиков на пищевом производстве (материалы, CIP-мойка).
- Сетевой сегмент и VPN-доступ к 1С согласуются с ИТ/ИБ заказчика.

## 5. Что не входит в проект (Out-of-Scope)

- Дооснащение/модернизация самой производственной линии, замена SCADA.
- Серверное оборудование 1С и лицензии «1С:БИТ.Лаборатория» (зона заказчика, `cost/cost_estimation.md` §2).

# Черновик API-контракта веб-консоли (фронтенд ↔ бэкенд)

> ❗ Выбор технологии фронтенда — за заказчиком (**OQ-12** в `open_questions.md`): Jinja2+HTMX (рекомендация) / React+Vite+TS / Vue3+Vite. Контракт ниже не зависит от выбора.

**От:** коллега (фронтенд). **Кому:** ведущему (бэкенд). Точка состыковки по аналогии с I-4.
**Основа:** `ui_requirements.md` v0.3 (SCR-01…12, UI-01…08, ST-01…07), FR v1.1, NFR.
**Принципы:** фронтенд **никогда не обращается к 1С напрямую** — только к API AquaPredict (NFR-6 работает на бэкенде); все мутирующие операции пишутся в аудит (LGL-10) на бэкенде; формат ошибок единый.

## 0. Общие соглашения

- База: `/api/v1`; JSON; авторизация — сессия/JWT после `POST /auth/login` (механизм — решение по В-7.2); роли — RBAC-матрица `ui_requirements.md` §3, бэкенд проверяет права на каждый эндпоинт.
- **Индикатор синхронизации (UI-08, ST-07):** каждый ответ содержит `X-Sync-Status: ok|queue|error` и `X-Sync-Last-Ok: <timestamp>`; фронт рендерит баннер по заголовкам.
- Ошибки: `{ "code": "string", "message": "string", "details": {} }`; 403 при отсутствии роли.
- Пагинация: `?limit=&cursor=`, ответ `{ "items": [...], "next_cursor": "..." }`.
- Реальное время: алерты — SSE-поток `GET /ws/alerts` (или polling 5 с — решение при реализации; NFR-1 ≤ 5 с датчик→алерт не зависит от канала UI).

## 1. Аутентификация и сессия

| Метод | Путь | Назначение | SCR |
| --- | --- | --- | --- |
| POST | `/auth/login` | вход (логин/пароль или AD — В-7.2) → роль | — |
| POST | `/auth/logout` | выход | — |
| GET | `/me` | профиль, роль, права (для скрытия экранов по RBAC) | — |

## 2. Дашборд и алерты (SCR-01, ST-01; FR-05)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/alerts?status=&layer=&line=&limit=` | лента алертов: `id, party_id, param(TEL), risk_score, horizon, recommendation, source(Слой 1/2), status, critical` |
| POST | `/alerts/{id}/ack` | подтверждение ознакомления (NFR-4, критические) → аудит |
| GET | `/alerts/budget?line=` | потребление бюджета за час / лимит 10 (NFR-5) |
| GET | `/lines` | список линий и статусов партий |

## 3. Инциденты и вердикты (SCR-02; FR-06, FR-12)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/incidents?status=&party_id=` | список (ST-02: Новый/Подтверждён/Ложный_алерт/Закрыт) |
| GET | `/incidents/{id}` | карточка: атрибуты, ссылки на алерт/задачи/пробы, журнал событий |
| POST | `/incidents/{id}/verdicts` | создание `ВердиктИнцидента`: `{value: подтверждён\|ложное_срабатывание, reason_code, comment}` (В-1; причина из справочника `GET /verdict-reasons`) |
| GET | `/verdict-reasons` | справочник причин (для select в SCR-02.2) |

## 4. Телеметрия и лабораторные данные (SCR-02/SCR-04; FR-02, FR-08)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/parties/{id}/telemetry?params=TEL-06,TEL-07&window=2h` | ряды для трендов (`[{ts, value}]`; метка достоверности канала — FR-16.4) |
| GET | `/parties/{id}/lab-results` | результаты LAB-xx + сверка с нормативом (информационная, LGL-11) |
| GET | `/parties?status=` | партии из 1С (read-only, UI-06) |

## 5. Задачи поверх 1С (SCR-03; FR-06.4, FR-07)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/tasks?type=ca\|sampling&status=` | read-only список из 1С (ST-03): статус, исполнитель, время, приложения-флаги |
| GET | `/tasks/{id}` | карточка (рекомендованные шаги, история статусов) — без мутаций из веб-консоли, ссылка в 1С |

## 6. Метрики и рабочая точка (SCR-06, SCR-11; FR-13, LGL-09)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/metrics/model` | пофазные (послоные) цели/значения Recall/Precision/FPR/FNR/F1, Baseline, горизонт, бюджет, статус модели (ST-05) |
| GET | `/settings/operating-point` | порог, остаточные FPR/FNR, «утверждено эксплуатантом», история изменений |
| PUT | `/settings/operating-point` | изменение — только АДМ (SCR-11.2) → аудит |

## 7. Мониторинг и аудит (SCR-09, SCR-10; FR-16, FR-14)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/telemetry/health` | статусы датчиков TEL-01…13 (FR-16.1), буфер шлюза (FR-16.2) |
| GET | `/audit?from=&to=&user=&entity=&source=&category=` | журнал (LGL-10); выгрузка CSV — `GET /audit/export` (право РЛ/АДМ) |

## 8. Открытые для бэкенда

1. Механизм аутентификации (В-7.2) — влияет на `/auth/*`.
2. SSE vs polling для `/ws/alerts`.
3. Подтверждение: мутации задач КА из веб-консоли **не предусматриваются** (read-only поверх 1С, UI-06) — все изменения только в 1С.

# Тест-кейсы: симулятор датчиков и мок-1С

**Версия:** 0.1 (2026-10-13). **Автор:** коллега — по заданию ведущего («готовь тест-кейсы под симулятор/мок-1С»).
**Основа:** `qa/test_plan_draft.md` §3 (окружение), FR v1.1, NFR-1/2/5/6, BPMN UC1/UC2, `qa/acceptance_checklists_scr.md`.
**Статус:** исполнение — после назначения тестировщика и реализации симулятора/мока (зона ведущего, включено в план). Приоритет: 🔴 Must (блокирует приёмку R0) / 🟡 Should.

| TC-SIM-03 | 🔴 | **Резкая аномалия.** Скачок параметра на линии | Latency «показание → алерт» ≤ 5 с (замер фиксируется в отчёте) | FR-05.2, NFR-1 |

| TC-SIM-06 | 🔴 | **Рассинхронизация времени шлюза** (сдвиг меток на N мин) | Метки вне допуска помечены недостоверными; в матчинг «срез → проба» не попадают без коррекции | FR-02.6 |
| TC-SIM-07 | 🟡 | **Сигнал режима** run/stop/CIP (TEL-13) | Режим распознаётся как контекст-признак; правила не срабатывают на остановленной линии (нет ложных алертов на CIP) | FR-03, TEL-13 |
| TC-SIM-08 | 🔴 | **Шторм аномалий.** Симулятор генерирует 30+ событий риска за час на одной линии | Генерировано ≤ 10 алертов/час; лишние подавлены как дубли с признаком; **подавленные инцидент не создают** | FR-05.4, NFR-5, В-6 |
| TC-SIM-09 | 🟡 | **Смена линии/партии.** Симулятор переключает партию (регистрация новой в мок-1С) | Новая партия прочитана по OData, наблюдение начато ≤ 5 мин (допущение OQ-05), ряды привязаны к новой партии | FR-01.1/01.2 |

| TC-M1C-07 | 🔴 | **Синхронизация статусов задач.** В мок-1С задача переведена [Назначена → Выполнена, с приложением] | Статус прочитан, отображён в SCR-03; в аудите источник = «1С», различены категории | FR-06.4, LGL-10 |

| TC-M1C-10 | 🟡 | **Чтение результатов (LAB).** Новые утверждённые результаты в мок-1С | Связка «проба → срез 2 ч» создана; метка попала в очередь разметки; конфликт источников → карантин | FR-08.1/08.4, FR-11.1/11.2 |

## Порядок работы

1. Симулятор и мок-1С реализуются ведущим (R0); данные тест-кейсы — вход в их постановку (критерии «готово» для каждого инструмента = покрытие блоков A/B).
2. Исполнение — тестировщик после назначения; результаты NFR-замеров (TC-SIM-03, TC-M1C-08) — в отчёт к акту R0.
3. Дополнение кейсами UI-приёмки — `qa/acceptance_checklists_scr.md` (отдельный проход, не смешивать).

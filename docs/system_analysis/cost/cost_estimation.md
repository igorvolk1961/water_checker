# AquaPredict LIMS — Оценка стоимости проекта (Cost Estimation)

Метод и каркас оценки стоимости. Числовые значения — **пример/допущение** на основе FR v1.1/BPMN; заполнены два прохода: «порядок величины» (§6) и «уточнённая» (§3–§4, §8). Связан с `business_case.md` (ROI) и `backlog/product_backlog.md` (эпики → оценка).

## 1. Метод

- **Базовый метод — WBS** (декомпозиция по эпикам/работам) с оценкой по **трём точкам** (оптимистичная / реалистичная / пессимистичная, далее PERT-усреднение).
- **Проверочный метод — функциональные точки / метод аналогов** для независимой сверки порядка величины.
- Класс точности по проходам: **проход 1 ROM (±50 %)**, **проход 2 budget (±20 %)**.

## 2. Структура затрат (WBS)

**CAPEX (единовременные):**
- Анализ и проектирование (требования, архитектура, диаграммы).
- Разработка: backend, ML-модуль, frontend (дашборд).
- Интеграции: «БИТ:LIMS» (OData/HTTP), телеметрия (OPC-UA/MQTT).
- Инфраструктура (серверы/облако, промышленный шлюз).
- Тестирование и **валидация ПО** (ГОСТ ISO/IEC 17025-2019).
- Внедрение, обучение персонала, документация.

**OPEX (регулярные):**
- Лицензии (БИТ:LIMS, ML-библиотеки, облако).
- Поддержка и мониторинг.
- MLOps: мониторинг дрейфа, переобучение, доразметка.

**Резерв (contingency):** 15–25 % от суммы.

**Разведение затрат:** **разработчик** поставляет ПО **и оборудование** (датчики, IoT-шлюз, серверы, сеть — `hardware_requirements.md`); это входит в CAPEX проекта. **Заказчик** несёт лицензию «БИТ:LIMS» и её поддержку; при размещении в контуре заказчика — инфраструктуру площадки. В ROI бизнес-кейса CAPEX проекта (ПО + оборудование) сравнивается с экономией заказчика.

## 5. Формула итога

`Итого = Σ(ставка × часы) + лицензии + инфраструктура + contingency`

- **Проход 1 (ROM):** оценка «порядка величины» по UC1–UC8, NFR и допущениям (±50 %).
- **Проход 2 (budget):** уточнение после заморозки FR/BPMN и после заполнения таблиц §3–§4 (±20 %).
- Используется для ROI в `business_case.md`.

## 6. Проход 1 (ROM) — ориентировочный пример

Оценка «порядка величины» (±50 %), сделанная по UC1–UC8 и NFR **до** FR. Значения ниже — **пример/допущение**; заменяются фактическими данными команды.

| Блок | Часы (пример) | Роль |
| --- | --- | --- |
| Анализ и проектирование | 300 | аналитики |
| Backend | 900 | backend |
| ML-модуль (Слой 1 + Cold Start) | 600 | ML |
| Frontend (веб-консоль) | 400 | frontend |
| Интеграции (1С OData/HTTP, OPC-UA/MQTT) | 400 | backend/1С |
| Тестирование и валидация ПО | 300 | QA |
| Внедрение и обучение | 200 | аналитики/DevOps |
| **Итого** | **≈ 3100** | — |

При средней ставке (пример) ~2000 ₽/ч: `3100 ч × 2000 ₽ ≈ 6,2 млн ₽`; с contingency 20 % → **≈ 7,4 млн ₽ (порядок величины)**. OPEX/год (лицензии, поддержка, MLOps) — **≈ 1,2–2,4 млн ₽** (пример).

Сопоставление с бизнес-кейсом: экономия 0,4–2,4 млн ₽/год (`business_case.md`) при ROM-затратах проекта ~7 млн ₽ даёт срок окупаемости, требующий уточнения и, вероятно, расширения эффекта (снижение репутационных/нормативных рисков). Это нормальный результат ROM — он выявляет чувствительность до детальной оценки.

## 7. Допущения и риски оценки

- Ставки и часы — **пример/допущение**; уточняются командой/заказчиком (ASM-10).
- Оценка опирается на FR v1.1/BPMN коллеги (точки состыковки I-3, I-6, I-8).
- Риски: недооценка интеграций «зоопарка» оборудования, объёма валидации ПО, MLOps-поддержки.
- Митигирование: резерв 15–25 %, проверка методом аналогов.

## 8. Проход 2 (budget) — смета

**Стоимость ПО (разработка, CAPEX):** **≈ 7,09 млн ₽** (таблицы §3–§4).

**Оборудование (поставка разработчика, CAPEX):** **≈ 2,28 млн ₽** (§2).

**Итого CAPEX проекта (ПО + оборудование):** **≈ 9,37 млн ₽**; с резервом 20 % → **≈ 11,2 млн ₽** (класс точности ±20 %).

**Затраты заказчика (отдельно):** лицензия «БИТ:LIMS» и её поддержка; **OPEX/год** (поддержка, MLOps) **≈ 1,2–2,4 млн ₽**.

**ROI:** при экономии **0,4–2,4 млн ₽/год** (`business_case.md`) срок окупаемости CAPEX-проекта — **≈ 4,7–28 лет** (широкий диапазон из-за допущений). Вывод: прямой экономии недостаточно как единственного обоснования; ценность дополняется снижением репутационных и нормативных рисков (ТР ЕАЭС 044/2017) и предотвращением отзывов партий.

**Рекомендации:** (1) расширить расчёт эффекта (сокращение простоев, отзывов, штрафов, репутационных потерь); (2) рассмотреть фазовое финансирование MVP (Слой 1 + Cold Start, EPIC-02/03/08) с решением о Слое 2 по результатам (критерии перехода `10_*` §4).

# AquaPredict — Руководство пользователя

**Версия:** 1.0. **Статус:** документ поставки (ТЗ §5.7). **Для кого:** главный технолог, инженер КИПиА, руководитель лаборатории, ML-инженер.
**Принцип системы:** AquaPredict — советующая система («человек в контуре»): она предупреждает о рисках и рекомендует действия; решения и физические действия всегда за персоналом. Прогноз имеет вероятностный характер и не является основанием для браковки партии — юридически значимое решение о качестве принимает лаборатория в «БИТ:LIMS» (1С).

## 1. Вход и главное окно

1. Откройте веб-консоль в браузере (Chrome/Firefox, свежих версий) и войдите под своей учётной записью (вход — по учётным данным организации; см. администратора).
2. После входа вы видите экраны, доступные вашей роли:

| Роль | Доступные экраны |
| --- | --- |
| Главный технолог (ГТ) | Дашборд, карточка инцидента, задачи, аналитика партии, метрики |
| Инженер КИПиА | Мониторинг телеметрии, дашборд |
| Руководитель лаборатории (РЛ) | Статусы протоколов/ФГИС, аналитика партии, метрики, аудит |
| ML-инженер (DS) | MLOps-модуль, метрики, аналитика партии |
| Администратор (АДМ) | Все экраны + администрирование |

3. В шапке каждой страницы — **индикатор синхронизации с 1С**:
   - ● зелёный «норма» — данные актуальны;
   - ● жёлтый «очередь» — операции ждут отправки, данные могут запаздывать;
   - ● красный «ошибка» — поверх страницы баннер с временем последней успешной синхронизации; данные на экране могут быть неактуальны, изменения выполняйте в 1С.

## 2. Работа с предупреждениями (главный технолог)

### 2.1. Что вы видите на дашборде
- **Лента активных алертов:** критичность, партия, параметр (TEL-код), риск-скор (0–1), горизонт, источник (Слой 1 — правила / Слой 2 — ML), статус.
- Критическое предупреждение (> текущий порог) выделено красным, сопровождается звуком и **требует явного подтверждения ознакомления** — кнопка в строке алерта.
- Справа — потребление бюджета алертов (лимит 10/час на линию) и статус линий/партий.

### 2.2. Что делать при получении предупреждения
1. **Подтвердите ознакомление** (критическое — обязательно). Подтверждение фиксируется в аудите.
2. Откройте **карточку инцидента** по ссылке из алерта: тренды телеметрии, риск-скор, горизонт, рекомендованные шаги.
3. Оцените ситуацию. Это ваше решение как специалиста:
   - **Риск реален** → подтвердите риск и создайте задачу на корректирующее действие (создаётся автоматически в 1С с рекомендованными шагами);
   - **Ложное срабатывание** → зафиксируйте вердикт «Ложное срабатывание» и выберите причину из справочника. Прогноз был ошибочным — система учтёт это в обучении.
4. **Вердикт обязателен**: инцидент не перейдёт в «Закрыт», пока не зафиксирован вердикт. Пока инцидент открыт, закрытие партии в 1С заблокировано.
5. При подтверждённом высоком риске система может параллельно создать **задание на внеплановый отбор пробы** — лаборант получит его через 1С и отберёт пробу до того, как отклонение разовьётся.

### 2.3. Важно понимать
- **Результат корректирующего действия** (Выполнено/Отменено — фиксируется в 1С) — это не то же самое, что **вердикт по инциденту** (Подтверждён/Ложное срабатывание). Оба фиксируются, но это разные вещи.
- Вердикт технолога — **прокси-метка**: если лабораторный анализ потом противоречит вашему вердикту, приоритет у лаборатории, а спорный пример уходит на проверку (это защищает обучение модели от ошибок человека).
- ML-алерт **не является основанием для браковки партии**. Основание — лабораторный контроль и подписанный протокол.

## 3. Задачи: корректирующие действия и отбор проб

- Экран «Задачи» показывает задачи, созданные системой в 1С, **только для чтения**: тип, номер в 1С, партия, суть, приоритет («Срочно»), исполнитель, статус, связанный инцидент.
- **Все действия с задачей — в 1С**: назначение, выполнение, закрытие с фото/комментарием. Статусы автоматически синхронизируются обратно в консоль.
- Лаборант получает задание на внеплановый отбор штатными средствами 1С, подтверждает отбор сканированием штрихкода — дальше анализ идёт по стандартному процессу.
- При ошибке синхронизации список замораживается с временем последней успешной синхронизации — изменения в этот момент делайте в 1С.

## 4. Аналитика по партии (ГТ/РЛ)

- Выберите партию: график показывает телеметрию и лабораторные результаты на одной временной оси; пробы по алертам помечены.
- Показатели сверяются с нормативами (СанПиН 1.2.3685-21, ГОСТ 32220-2013) — **подсветка информационная**: если видите «Превышение», решение о несоответствии оформляется в 1С.
- На экране также: инциденты партии, задачи, статус блокировки закрытия.

## 5. Мониторинг канала телеметрии (инженер КИПиА)

- **Статусы датчиков TEL-01…13**: Норма / Нет данных / «Заморожено» (значение не меняется) / Вне диапазона / Задержка потока — с временем последней валидной отметки.
- **Буфер шлюза**: заполнение, глубина при потере связи (до 2 ч), синхронизация времени. При потере связи не отключайте шлюз — данные сохранятся и досинхронизируются автоматически.
- При аномалии потока система уведомляет вас; после устранения неисправности подтвердите восстановление — данные снова пойдут в оценку риска. Инциденты, рассчитанные по деградировавшему каналу, помечены как менее достоверные.

## 6. Метрики модели (DS/ГТ/РЛ)

- Показатели отображаются **раздельно по Слоям** (правила и ML) вместе с целями и Baseline (ситуация до внедрения).
- **Рабочая точка** (порог критического алерта и принятые остаточные ошибки) утверждена эксплуатантом — изменить её может только администратор, история изменений сохраняется.
- Статусы моделей: Shadow (обучение и накопление статистики, персоналу не показывается) → Advisor (советник) → Production. Дрейф данных контролируется непрерывно.

## 7. Частые вопросы

**«Почему я не могу ввести результат анализа в системе?»**
Журнал проб, результаты и протоколы ведутся в «БИТ:LIMS». Система читает их оттуда — двойной ввод исключён.

**«Почему система не остановила линию?»**
Система не управляет оборудованием (принцип HITL) и не дублирует защитные автоматики. Она предупреждает заранее — решение принимаете вы.

**«Алерт оказался ложным — что делать?»**
Зафиксируйте вердикт «Ложное срабатывание» с причиной. Это нормальный рабочий процесс: точность системы растёт в том числе на ложных срабатываниях.

**«Куда смотреть, если данные выглядят устаревшими?»**
На индикатор синхронизации в шапке. Красный — изменения только в 1С до восстановления связи.

**«Кто видел моё подтверждение?»**
Все действия фиксируются в неизменяемом аудите: что сделала система, что решил человек, что выполнено фактически (в 1С). Аудит доступен РЛ и администратору.

# EPIC-02 — Сбор телеметрии и привязка к партии

- **Релиз:** R0 · **Оценка:** 360 ч / 800 000 ₽
- **Источники:** US-02.1 · FR-02 · SCR-01/09 · C4-2 (контейнер «Приёмник телеметрии»), C4-3 (`QUAL`) · NFR-1/2/3/7
- **Цель:** принимать телеметрию TEL-01…13 с контролем качества потока и буферизацией.

## Задачи

- T-02.1 Приёмник OPC-UA (`asyncua`) и MQTT (`paho-mqtt`), частота ≥ 1 изм./мин.
- T-02.2 Валидация меток времени (NTP, допуск) — FR-02.6.
- T-02.3 Буферизация на шлюзе до 2 ч + автосинхронизация в исходном порядке (NFR-2).
- T-02.4 Привязка рядов к партии без дублей; хранение (партиционирование), retention 1 год (LGL-06).
- T-02.5 Контроль качества потока (пропуски/«заморозка»/диапазон) → события в EPIC-14 (FR-02.4).
- T-02.6 **API-компонент телеметрии:** `/telemetry/ingest`, `/telemetry/latest?sensor=`, `/telemetry/health`.
- T-02.7 **Имитатор датчиков:** OPC-UA-сервер/MQTT-публишер с настраиваемыми TEL-профилями (норма, деградация, дефект) — для разработки и тестов без линии.
- T-02.8 Нагрузочный тест latency ≤ 5 с (NFR-1).

## Зависимости

- EPIC-01 (партии). Опираются: EPIC-03, EPIC-08, EPIC-14.

## Definition of Done

- Ряды принимаются и привязываются; буферизация и досинхронизация работают (на имитаторе); latency ≤ 5 с; retention соблюдается.

## Риски

- Доступ/адресация OPC-UA; рассинхронизация времени (PRJ-01).

# AquaPredict — Спецификация варианта использования (Detailed Use Case)

Самый важный артефакт для демонстрации глубины проработки. Взят главный отличающий сценарий. Приведено в соответствие с вариантом A (надстройка над «БИТ:LIMS»): действия с задачами выполняются в 1С, AquaPredict отображает их read-only.

## Обработка предиктивного предупреждения о риске отклонения качества

- **Основной актер:** Главный технолог.
- **Вторичный актер:** ML-модуль (риск-скоринг, Слой 1/2).
- **Предусловие:** производственная линия работает, данные с датчиков поступают в систему, движок риск-скоринга активен.

### Основной поток (Main Flow)

1. Движок риск-скоринга (Слой 1/2) непрерывно анализирует агрегированные данные с датчиков (например, падение давления на фильтре + рост температуры в цеху).

2. Движок вычисляет риск-скор отклонения целевого показателя (например, ОМЧ) свыше нормы в пределах горизонта упреждения (например, 2 часа).

3. При превышении **настроенного порога алертинга** формируется событие `RiskAlert` с параметрами: `партия_id`, `параметр_риска`, `риск_скор`, `горизонт`, `рекомендуемое_действие` (например, «Промыть фильтр №2»), `источник` (Слой 1/2).

4. Система создаёт запись «Предиктивный инцидент» со статусом [Новый] и блокирует возможность закрытия партии без проверки (FR-01.4).

5. Система отправляет Push-уведомление и SMS главному технологу.

6. Технолог открывает инцидент в веб-консоли, изучает тренды телеметрии и рекомендацию.

7. Технолог подтверждает риск; система создаёт в «БИТ:LIMS» (1С) **задачу на корректирующее действие** с рекомендованными шагами. Персонал выполняет действие на производстве и закрывает задачу **в 1С** (назначение, закрытие, фото/комментарии — в контуре 1С).

8. Система читает статус задачи из 1С (результат [Выполнено]); технолог фиксирует **вердикт по инциденту** [Подтверждён] (отдельная аудируемая запись); система переводит инцидент в [Закрыт] и снимает блокировку закрытия партии.

### Альтернативный поток 3а. Ложное срабатывание (False Positive)

- В шаге 6 технолог проверяет показатели и видит, что они в норме, а рекомендация неприменима.

- Технолог фиксирует **вердикт** [Ложное срабатывание] с указанием причины из справочника; инцидент переводится в [Ложный_алерт].

- Данные инцидента отправляются в ML-модуль как размеченный пример для дообучения модели (Feedback Loop, FR-12).

### Альтернативный поток 3б. Результат корректирующего действия [Отменено]

- Если задача в 1С закрыта с результатом [Отменено], инцидент возвращается главному технологу на пересмотр (новая рекомендация либо вердикт [Ложное срабатывание]) — FR-06.6.

### Постусловие

- Инцидент закрыт (успех, ложное срабатывание) либо возвращён на пересмотр; задача закрыта в 1С; вердикт зафиксирован; данные, при необходимости, использованы как обучающий пример для ML-модели.
